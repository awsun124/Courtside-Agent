# Project style

- Use clear, natural wording in code, documentation, reports, and commit messages.
- Choose descriptive variable and function names. Avoid cryptic abbreviations.
- Keep filenames and folders simple and consistent. Avoid unnecessary nesting.
- Keep comments short and occasional. Explain a surprising choice when needed.
- Do not use em dashes or semicolons in comments or docstrings.
- Keep API keys in the local `.env` file. Never print or commit them.
